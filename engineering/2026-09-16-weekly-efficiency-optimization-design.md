# 七份周报执行效率优化方案

日期：2026-09-16（Asia/Shanghai）

状态：**设计完成，尚未实施**。本轮只读复盘并归档方案；不修改生产Prompt、Skill、Cron、模型、时限、并发、权限或历史发布内容，不重跑周报。

## 一、决策摘要

**建议优化共用流程，不再给七份Prompt各加一套规则，也不靠减少研究、取消质检或延长时限获得“提速”。**

先做P0：统一冻结前格式/发布参数检查，消除冻结后纯格式返工，准确记录阶段状态。再做P1：压缩账本重复表达、简化中间交接审阅、提前明确汇总责任。最后通过正常出刊验证跨主题收益，再考虑来源材料复用及资源安排。

今日资本周报已采用“研究并行、文章/盲提取并行、同一编辑续做、局部修订”，这些不是待新增能力。真正问题主要在**已写规则没有有效落实、不同检查器口径不一致、中间交接重复阅读、审计文本反复展开**。部分建议只是落实既有规则；涉及行为变化的部分须另行授权、测试和生效。

## 二、证据与边界

### 2.1 实测样本

今日资本周报原生运行从10:00:00至13:28:00，实际耗时 **3小时28分0.688秒**，原生状态`ok/succeeded`，投递`delivered`；业务为`SUCCESS_WITH_WARNINGS`。正文与头图均已验证上线。

下表来自生产审计的阶段节点，**是近似跨度，不是逐工具性能计时**：

| 阶段 | 审计时段 | 约占用 | 含义 |
|---|---|---:|---|
| 研究、汇总、准入和编辑准备 | 10:00—11:20 | 80分钟 | 包含研究、子汇总、父级审阅及准备；不全是搜索 |
| 文章初稿、盲提取、协调与父级验收 | 11:20—12:26 | 66分钟 | 包含必要审查，也存在重复表达/中间读取候选 |
| 发布准备、格式返工、两次构建、推送与线上验证 | 12:26—13:21 | 55分钟 | 不可把全部时段都算Git或构建耗时 |
| 终态整理至原生finished | 13:21—13:28 | 7分钟 | 含记录、最终响应/运行收尾，无法细拆 |

### 2.2 已证实的问题

1. **格式预检漏掉下游会拒绝的格式。** 研究母稿冻结前`check-inputs`通过，但该工具只检查安全文件、UTF-8、EOF等，未覆盖中间行尾空格。三行题头Markdown双空格直到构建后提交检查才发现，导致母稿SHA变化、多个标记更新和二次构建。现行规范已要求构建前`git diff --check`，但本期没有有效提前检出；缺原始工具日志，不能断言命令从未执行。新/未跟踪文件还需确认是否进入diff检查范围。
2. **初始发布合同含错路径。** 合同写了带`/ai/`的正文URL与`/assets/images/`图路径；实际站点permalink不含分类目录，检查器要求`/assets/images/posts/`。最终修正成功，但这类参数错误本可提前拦截。
3. **构建失效边界偏宽。** 当前postbuild把资料库研究母稿mtime也当作博客构建新鲜度依赖；仅母稿题头格式变化、博客文章未变，仍触发重建。当前执行遵守了现行规则，未来应测试按真实依赖拆分，而不是忽略mtime或伪造构建时间。
4. **审计材料体积较大且含具体重复。** 正文32,215字节；首次清单36,835、独立清单67,964、映射81,289字节，三材料合计186,088字节，是正文的 **5.78倍**。存在同一清单反复复述背景、来源边界、映射等义项长段重写；大小本身不证明冗余比例。
5. **协调前后父级各做了一次四文件全文读取。** 编辑Phase1自检、父级中间全文读取、原编辑协调与最终审阅、父级最终全文验收形成较长链路。父级最终验收不可删；中间是否需要再做一次完整语义审阅可调整。未变规则在同编辑续做时重新全读的净收益还须测量，不能假设上下文一直保留。
6. **当前状态更新滞后。** 12:12写入的audit当前阶段直到13:16查询时仍停在12:11/article；文章已完成、双仓已提交，状态还显示待验收。最终补齐了记录，但中途查询必须重复查文件/Git。

独立盲提取本期促成 **F2/D1/J5，共8项基线补漏**，说明它有真实价值；其中部分正文原已保留，不能说修了8个正文漏项，更不是8次独立事实验证。

### 2.3 不能据此下的结论

- 未取得生产父/子逐轮工具时间线；会话访问范围受限，未绕过限制读取转录存储。精确排队、模型、工具、纯空闲时长和调用次数未知。
- 600秒wait是最长检查段，每30秒检查、就绪即返回，不是固定空等10分钟。不能把WAIT_TIMEOUT相加当可节省时长。
- 原生usage大部分是累计缓存读取；不能当唯一上下文、新增token或直接换算费用，也未确认其是否覆盖所有子任务。
- 不能保证节省30%或若干分钟；两次构建间约17分钟包含多种返工，不等于一次构建用了17分钟。
- 历史任务的原生错误与业务发布结果需分别核实，不能把所有超时都归流程、把所有原生ok都归质量通过。

## 四、目标流程与职责

```text
解析本期主题参数与真实发布配置
  ↓
研究组在独立写域并行研究
  ├─ 已完整交接的材料，父级可先验收
  └─ 活跃未交接文件，只看进度，不当定稿
  ↓
单一母稿负责人汇总 → 研究准入 → 格式兼容检查 → 冻结
  ├─ 原编辑：首次清单 → 读者稿 → 逐章映射
  └─ 隔离盲提取：第二清单 → 独立冻结交回
        ↓ 两份原清单冻结且写权交回
原编辑协调差异 → 局部修改 → 全文双向/阅读复核
  ↓
父级最终完整验收母稿、两清单、映射与文章
  ↓
唯一发布者：prebuild → 真实build → postbuild
  → 双仓提交/远端验证 → 正文及头图线上验证 → final/announce
```

头图在选题稳定、依据和授权满足后可独立准备，不阻塞已满足条件的文章线；发布前必须完成验证。资源不足时双线可串行，但盲提取隔离不变，不能让编辑占住唯一槽位等待尚未启动的盲提取。既有并发额度不等于共享仓库锁，仓库冲突仍停在冲突写边界。

### 唯一权威划分

| 所有者 | 只负责 |
|---|---|
| 七份主题Prompt | 范围、时间窗、分组、专业取证和判断、目标、主题产物/发布参数 |
| cron-run-reliability | run身份、写域、等待、恢复、状态与终态 |
| industry-research-evidence | 事实证据、归因与研究准入 |
| 现有handoff协议 | 研究到编辑的公开边界与角色交接 |
| 工作区report2article及其references | 原子清单、去重改写、差异协调、全文保真和阅读验收 |
| weekly-publication及既有固定工具 | 格式、路径、外壳、构建、Git、HTTP的机械验证 |

整理采取“旧规则逐条找到唯一落点，再删除主题中的同义重复”，不是先删规则或另建一个效率Skill。七份主题完整专业要求不被压成几行关键词；不新建DAG、执行器、锁服务、数据库或第四套完整账本。

## 五、六个优化工作包

### P0-A：让冻结前检查真正覆盖发布兼容性

**目的：避免为了几处空格和路径，在文章验收后改SHA。**

- 在现有固定检查器及契约中补齐会被后续Git拒绝的格式检查，覆盖新/未跟踪文件，不只依赖普通`git diff`。
- 合法Markdown双空格硬换行不能全局`rstrip`；检查只报告，由唯一写者安全改写并核对受影响渲染与语义。代码块空格不得误改。
- 在既有任务合同中解析并验证站点URL、图目录/文件名、分类、bucket和正文外壳边界；同一值集中一次，后续引用。
- 母稿准入和格式均通过后一次冻结；叠加外壳后prebuild再确认完整字节对应；保留提交前检查。

**性质：** 构建前检查是既有规则落实；冻结前整文件覆盖、契约与工具对齐是待授权变更。

**验收：** 新文件题头空格、错图路径、错误分类URL等在冻结/构建前被发现；硬换行/代码块不会被误修。不能以假SHA或跳过检查换取成功。

### P0-B：按真实依赖决定哪些证据失效

**目的：纠错只重验受影响边界，不无条件带来重写和重建。**

| 变化 | 必须重验 | 有条件保留 |
|---|---|---|
| 母稿新增事实、数字、判断或公开边界 | 研究准入；受影响清单/映射/文章；最终全文保真 | 未受影响且有证据的其他研究材料 |
| 母稿纯格式、可见内容与语义未变，博客正文未变 | 精确差异、源SHA、归档字节、版本过渡、相关标记 | 原始独立清单作为旧输入真实证据；确认真实渲染依赖未变后，可保留博客build证据 |
| 文章、front matter、图像、站点配置/依赖变化 | 对应语义/外壳检查；真实build/postbuild及之后版本验证 | 无关研究与原始提取证据 |
| 已验上线后仅通知失败 | 通知状态/投递 | 已验证研究、文章、构建及发布结果 |

**性质：** 现有规则已允许受影响边界重验；具体博客构建依赖范围须改固定工具及契约并测试，未实施前继续遵守旧规则。

必须排查Jekyll插件/配置是否间接读取母稿；依赖未知时不复用。复用证据绑定内容hash、配置/依赖版本、真实构建起止/exit和当前输出，**不是关闭mtime检查**。不新增数据库或自动恢复服务。

**验收：** 仅资料库格式变化不误使无关build失效；任一真实渲染输入、依赖或产物改变必须拒绝旧build。源SHA、归档完整字节和最终全文验收仍有效。

### P1-C：让审计账本记录证据，不反复复述原文

**目的：降低生成和回读负载，保持每条语义可还原。**

- 每份独立清单内部，对象、共同限定、来源只定义一次，F/D/J用稳定可解析引用；两份清单不能共享提取结果。
- 等义映射用“双方编号＋母稿位置/关键语义＋准确文章落点＋状态”；跨类、拆并、真实差异及来源争议详细解释。
- 保留原计数与补漏区，不靠改成同数制造一致；不再生成第三套最终清单或第四本账。
- 避免深层引用、悬空引用和歧义短语；“非新法”不能缩成“非法”。不设账本字数硬帽，不移动公开边界来减少销账。

**性质：** 主要是落实已存在的紧凑表达要求，必要时补明示例；不是取消清单。

**验收：** 本期F72/F73/D61/J44—J48等类型的漏项仍可发现；每个编号的主体、期间、单位、分母、归因、限定、判断强弱和来源支撑可逐项恢复；最终父级全读、双向审查不减。体积下降不是验收充分条件。

### P1-D：中间交接从“再做一遍终审”改为“安全交接”

- Phase1父级检查写者交回、两原清单冻结版本、文件完整、明确阻断项；有具体疑点就读受影响内容。**不在协调前无条件再做四文件完整语义终审。**
- 原编辑接收第二清单后继续，不另派协调者冷启动。
- 同编辑、同规则/母稿版本、前次完整读取有证据且上下文仍可用，未变规范按需回查；换人、版本变化或上下文缺失则恢复必要完整读取。不能只看SHA就宣称掌握语义。
- 新到的第二清单完整读；两侧映射逐项打开核对；编辑者最终双向/阅读验收、父级最终全文及三材料验收全部保留。

**性质：** 中间门控安排可在现行框架下调整；连续阶段规则重读条件需澄清，不私自跳过明确必读要求。

**验收：** 版本/写权/截断等问题中间就发现；最终内容缺陷不增加；记录早读独有纠错价值和最终返工，若移除中间全读导致质量或净效率变差则撤回。

### P1-E：汇总责任提前定，不在父级读完后才临时再派一轮

本期约10:39另派汇总者；父级此前已读全部研究交接，汇总者再次装载输入，之后父级又验收母稿。这样有专业分工价值，但不是每份周报都需要无条件增加一棒。

- 运行合同启动时指定唯一母稿负责人：父级直接综合，或预先确定独立汇总者，二选一，不为这一步固定增加新Agent。
- 父级已承担充分研究综合且预算/能力适合时直接成稿；确需汇总者则从开始明确职责和只读输入，在已有额度内利用已交接材料。
- 父级保持跨组冲突判断、主题要求的风险抽查和最终准入，不把生产者自检当最终事实验收。
- 同一对象唯一主责；按原文/附件/政策/技术风险工作量分配，不能仅均分公司数。光谷3组、具身研究预算和模式等保持。

**性质：** 职责安排优化，具体收益待测；不是全面禁止汇总子任务或减少独立复核。

**验收：** 比较实际冷启动/重复装载和父级负载，研究范围与主张正确性不降；不能减少有必要的独立风险复核来报提速。

### P0/P2-F：状态与时间口径清晰，再做跨周报复用

**立即优先：** 每次真实阶段转换更新原audit当前区，记录进入/就绪/接收时间、输入版本、缺口和下一步；没有可观察时间就写未知。状态不等于进度百分比，不另建日志流水线。

**必须分开四种时间：** 报道事件窗口、采用信息的as-of截止、实际读取时间、研究冻结时间。本期在10:00启动又写10:00检索截止，容易把正常执行后检索一律标成越界。若截止表示内容采用上限，可晚些读取但不能采用截止后新增事实；若页面版本无从确认就限述/隔离。语义不明先澄清，不能移动窗口吸收新新闻。

**后续可选：** 在既有研究库复用已读、可定位、版本与日期明确的原文证据，不复制其他周报结论或验收；动态页面/政策/价格重新核实。一个事件可以在企业、Agent、产业、资本报采用不同角度，不能被全局去重删掉。保持每主题完整扫描，不建立新数据库。

**资源处理：** 现有额度内并行独立只读检查，等待间做独立验收；不缩短成高频轮询，不用不可见状态推断写者结束。服务级401/403与单站失败分别记录，按已授权备用处理，不绕过访问限制。

**验收：** 查询状态与真实阶段一致；只在具备证据时计算生产者就绪到父级接收延迟；跨主题复用不漏新变化、不把转载变独立来源。周一竞争风险观测明确后再提出是否错峰的单独决策，本方案不改排程。

## 六、实施与验证顺序（均待授权）

1. **静态设计与反例**：先做P0格式/路径和工具契约；逐条建立旧规则到唯一所有者的对应。只在隔离测试目录使用样本，不重跑七份生产研究。
2. **隔离同稿验证**：针对紧凑清单/中间门控等行为变化，用同一冻结母稿离线比较，禁止联网补事实、禁止推送；两线独立性仍保持。语义测试包括金额上限、来源归因、样本分母、未来交付、否定边界、跨类别漏项和无源增写。
3. **安全维护窗口**：无活跃任务依赖旧规则时才应用经批准变更；共享文件同时影响所有后续读取者，不能声称“只对资本开启”。不为灰度新建版本路由/feature flag。
4. **自然周期分批观察**：先观察下一份正常任务，再覆盖光谷3组、2小时技术/产业类、4小时资本/具身类，最终覆盖全部七类。没有该类观测就不宣称已验证；不额外双跑研究。
5. **多期同质量比较**：记录每主题信息量、实际精读量、公开原子信息量、风险主张与外部服务状态后再比较。自然周内容不同，不直接比较总时长得因果结论。
