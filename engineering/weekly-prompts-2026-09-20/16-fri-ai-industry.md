### ⚠️ 分批落盘（铁律，根治输出截断 ≠ 牺牲深度）

**严禁一次性在对话里编译/输出整组完整报告**——单轮模型输出有 ~4096 token 硬上限，一次吐整组会被 `stopReason=length` 截断成半截（已实测踩坑）。分批落盘是为了**抗截断**，不是让你写短。

正确做法：
1. 黄山每研究完 **1-2 个对象**，立刻用 `write` 写入独立分片文件：`<RUN_DIR>/<组名>-part-<序号>.md`（`<RUN_DIR>` 是下文登记的绝对运行目录，原分片 basename 不变）。禁止覆盖既有分片，禁止用 `exec` heredoc、内联脚本或临时 Python 追加内容。全部分片完成后，用 `read` 逐片复核；最终母稿由小帅通过 `write` / `edit` / `apply_patch` 分块落盘。
2. 重复直到本组全部产业+对象落盘。确认每个有料对象都写够深度。
3. 最后输出非空简短交接：说明 X 组单一当前 status、已写入 <文件路径>、共 N 个对象/有料 M 个（含政策 K 篇均读原文）及缺口；status 与 `.done` 一致并按统一执行规范第2、3节解释，不把未完成写成完成。**不要把报告正文再贴回对话**。
4. 主会话/小帅汇总时直接 `read` 这些中间文件。

## ⚠️ Markdown 格式铁律（kramdown 渲染兼容，每期发布前必查）

博客引擎是 Jekyll + kramdown：
1. **表格前必须有空行**：任何表格上方必须隔一个空行，绝不能紧贴标题。
2. **表格行绝对禁止前导缩进/禁止写进列表项**：表格每行必须顶格，表格块独立成段（前后各一个空行）。要在列表项里带表格就用 `**xxx：**` 独立加粗段落引出，下空一行再顶格写表格。
3. **标题层级严格分层**：顶层主节用 `##`，子节层级合法；5 个一级行业及各二级行业的速查表、状态与深度正文信息必须完整保留，行业归属清晰。章节划分与具体呈现交给 `report2article`，不固定每行业一个 `###`。
4. **赛道/产业信息清楚分隔**：采用 Skill 决定的章节、表格或段落组织，不另定机械目录。
5. **🔴 箭头因果链/传导链禁用 ``` 代码围栏**：一律用加粗小标题 + blockquote 引用块（2026-07-07 踩坑：代码围栏被 Jekyll 渲成黑底代码框，看着像没渲染对）。
6. **发布前自检（必跑）**：
   - `awk '/^### / {h=NR} /^\| /{if(NR==h+1) print "⚠️紧贴标题:"NR}' 文件` —— 输出为空才合格
   - `grep -c '```' 文件` —— 应为 0（除非确有真代码）
   - `grep -c "^## " 文件` —— 仅辅助检查标题层级，不以主节数量限制 Skill 的章节组织
   - 链接一律 `[名](url)`，不裸贴 URL
