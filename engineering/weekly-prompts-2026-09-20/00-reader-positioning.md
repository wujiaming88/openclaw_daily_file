# 读者定位与信息需求（七份周报共享规范）

> 老板定位：**AI Agent infra 架构师 + 解决方案专家**。
> 本文件统一规定七份周报「为谁写、解决什么需求、用什么透镜」。各主题 Prompt 只声明自己主责的需求编号，不重复定义透镜内容。
> 本文件是**输出视角规范**，不是研究范围扩张授权。它改变的是「同一批已取证素材如何组织与提问」，不新增检索义务。

## 一、老板的四项信息需求

| 编号 | 需求 | 他要的实质 |
|---|---|---|
| R1 | 最新技术与产品动态 | 不是新闻摘要，而是「这对我搭方案意味着什么」：能力边界、可用性、成熟度、坑 |
| R2 | 丰富的落地案例 & 应用场景 | **解决方案视角**：怎么搭的、交付给谁、什么代价、踩了什么坑、能否复制 |
| R3 | 上下游更多进展 | **价值链视角**：链条位置、供给与需求传导、谁在往哪段挤、价值与议价在何处 |
| R4 | 资本市场与创业资讯 | **从业者视角**：竞品融资、赛道热度、估值风向、细分进退潮、并购与整合 |

## 三、解决方案专家透镜（R2 核心，主责：周五）

研究到「落地案例」时，除现有事实与效果，**必须尽量补齐以下五要素**；某要素确实未公开时，写明「未披露」，不得用推测填充。

1. **怎么搭的**：技术路线与架构组合、用了哪些组件/模型/框架、自研与采购的边界、集成方式。
2. **交付给谁**：客户与行业、使用角色（采购者/使用者/验收者）、部署形态（SaaS/私有化/混合）、规模（用户数/门店数/产线数/调用量）。
3. **什么代价**：投入量级、上线周期、单价或收费模式、人力与运维负担、总拥有成本；只写已披露口径。
4. **踩了什么坑**：失败与回退、效果不达标、数据与集成难题、组织阻力、合规与安全事件、项目中止。
5. **能否复制**：可迁移到哪些相近场景、成立的前提条件（数据基础/流程标准化程度/组织配合）、不成立的边界。

**写作铁律**：演示 ≠ 规模部署，试点 ≠ 付费交付，采购 ≠ 收入。区分清楚并保留归因。

## 四、价值链透镜（R3 核心）

沿链条定位每个对象，并回答「价值与议价在何处」：

```
模型与算法 → Agent 运行时/Harness → 协议与工具生态 → 平台与工具链
        → 系统集成与交付 → 终端场景与客户
```

对每个关键对象尽量标注：

- **链条位置**：处在哪一段，向上一段买什么、向下一段卖什么。
- **传导方向**：本周变化沿链条向上还是向下传导，谁受益、谁被挤压。
- **价值与议价**：增量价值落在哪一段；是否出现「谁被商品化（commoditized）」「谁掌握定价权」的信号。
- **供给与需求**：上游产能/供给变化，下游付费意愿变化。

**边界**：链条位置判断必须有证据支撑；无法判断时写「位置待明确」，不硬贴标签。

## 五、从业者资本视角（R4 核心，主责：周三）

在既有投资漏斗之外，**额外**输出面向产业从业者的市场资讯：

- **竞品融资**：直接竞争赛道的公司融资、并购、上市动作。
- **赛道热度**：细分方向的资金流入/流出、交易数量与节奏变化。
- **估值风向**：估值口径变化、融资条款与结构信号（仅写已披露口径，不推测）。
- **进退潮**：哪些细分正在起势、哪些在降温或整合出清。
- **对从业者的含义**：这些资本信号说明什么样的能力与方案正被市场定价。

**边界**：不做二级市场荐股，不给买卖点，不构成投资建议。

## 六、增强方式铁律

1. **只重构视角，不扩大检索**：本规范要求的是对已取证素材换提问方式与补产出字段，**不新增必查对象、不新增并行研究组、不延长检索清单**。当前七份任务的超时预算未变，不得因此增加单期工作量。
2. **不降低证据标准**：新透镜下的每一句判断仍须走原周报的证据分级与限述规则；未披露就写「未披露」，宁可空缺不推测。
3. **不新增执行机制**：本规范不新增任务、执行器、自动恢复服务，不改日程、模型、超时、并发、权限与发布流程。
4. **冲突时以主题 Prompt 为准**：主题 Prompt 的研究范围、时间窗、准出规则优先；本规范只在视角与产出字段上补充。
5. **反漂移**：本规范不把周报变成「方案推销」或「赋能套话集」；不因加入透镜而降低事实密度，也不把无证据的行业想象写成案例。
