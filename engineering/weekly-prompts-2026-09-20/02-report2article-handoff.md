## 一、职责边界

### 周报 Prompt 负责研究与决策内容

周报 Prompt 必须完成：

- 时间窗、地域、对象、模块和行业范围；
- 原始来源阅读、事实核验、数据口径与交叉验证；
- 研究覆盖率、专项要求、技术/商业/政策分析；
- 对事实作出有证据支持的判断，并标明不确定性；
- 产出一份已经完成研究、可独立审阅的“研究母稿”；
- 资料库和博客的目标路径、front matter、主题头图等发布参数；构建、Git、HTTP 的执行顺序统一引用执行规范第6节。

周报 Prompt 不再自行维护另一套标题、章节、去重、读者化、长文分块或信息销账规则。

### report2article 负责文章编辑

研究母稿通过周报质量门控后，必须读取并严格执行当前工作区安装版：

`/root/.openclaw/workspace/skills/report2article/SKILL.md`

由该 Skill 负责：

- 建立 O/F/D/J/L 原子信息基线；
- 识别并合并不承载独立信息的重复表达；
- 选择一条读者主线，重组章节和段落；
- 设计客观标题、自然子标题和纯导航过渡；
- 在事实与证据不变的前提下做读者型改写；
- 长报告分块编辑、逐块落盘、逐项销账；
- 正向覆盖、反向溯源和长报告独立二次派生；
- 给出最终信息校验：`O 个对象 / F 条事实 / D 个数据点 / J 条判断 / L 个唯一链接，全部可追溯`。

工作区路径 `/root/.openclaw/workspace/skills/report2article/` 是本流程唯一的已应用权威来源；执行时实际读取该路径下的 SKILL.md 及其引用文件，并将绝对路径和版本/SHA传给编辑与复核者。`/root/.openclaw/skills/report2article/` 是历史兼容副本，不作为本流程输入或回退来源，不声称两处已经同步，不混用版本。工作区必需文件缺失、不可读取，或与本次冻结规则版本不符时停止交接并报告；不得自行猜测或拼接其他版本。

## 二、交接顺序

1. **研究线落盘**：各研究组只负责原始证据与专业分析，不写博客成稿。每次研究、编辑、盲提取或接续协调委派，先按统一执行规范第3节填写并直接传入预算合同，不以文件路径引用代替实际截止与剩余量；不在此复制字段或另设时限。启动合同指定唯一母稿负责人：父级直接综合，或在现有额度内预定汇总者；不在父级已承担综合后无条件再派一轮同职责写手。对同一对象按专业取证负载指定主责，保留各主题扫描与独立风险复核；已完整交回的材料可先验收，未交接版本只看进度。
2. **统帅验收研究母稿**：母稿负责人统一事实口径、结论和风险，父级保持跨组冲突处理、规定的风险抽查和最终研究准入；不以生产者自检代替父级验收。先按共同标准逐主张处置，研究审查不得包含任何“report2article 已执行”条件。覆盖率、候选数、TOP5数、双源数、抽查数和字数未达目标时如实列局限，不因此循环回炉。合同分别记录报道事件窗口、信息采用截止、实际取证时间和研究冻结时间；窗口及截止仍服从主题，不因检索发生在启动后而移动窗口，也不把较晚读取冒称截止前的页面版本。截止后新增事实不纳入，无法确定版本的主张限述或隔离。已有来源材料仅在日期、版本、适用范围与可读原文确证时复用，各主题重新判断相关性与证据强度；动态状态重核，不沿用另一周报的准入结论或减少本主题扫描。
3. **冻结公开边界**：冻结前把母稿内容标记为 `PUBLIC_CONTENT`（进入 Skill 基线，独立信息必须保留）、`AUDIT_METADATA`（仅留资料库）、`PRIVATE_INTERNAL`（禁止传给 Skill）或 `EVIDENCE_ONLY`（可进公开来源附录，不强制进入正文）。冻结前的格式预检直接引用统一执行规范路由的 `cron-run-reliability/references/weekly-publication.md`，本协议不重定义格式规则。后续编辑不得自行补事实、补背景或改判断。发现事实/来源缺口时，先由研究端按共同标准判断：可限定则限述，可隔离则排除并复验受影响判断；只有仍拟保留且确需补证的核心主张才做有界补证。形成新版母稿并只重验受影响边界后重新冻结，不要求所有缺口一律补齐，也不反复回炉已合格内容。
4. **执行 report2article**：以“完成准入审查并冻结的最终研究母稿文件”为唯一内容输入，不能直接把 A/B/C/D 研究线、证据账本或旧博客当成并列输入。研究冻结后，在现有并发额度内尽早启动两条分离写域的工作线：编辑线从首次清单继续正文与映射；独立盲提取线只读冻结母稿及其公开边界，使用 `context="isolated"`，不得接收或读取首次清单、文章内容或编辑线映射。两份原始清单均完成并冻结后才能协调差异。若现有资源不足，改为串行但仍保持盲提取输入隔离；不得配置并发扩容，也不得为此虚构模型路由或超时时限。按 Skill 完成信息基线、读者主线、去重、重组、改写和复核；编辑发现缺口时不得自行研究或补写，须标出受影响主张并回到上一步做限述/隔离/有界补证，然后基于新版冻结母稿复验受影响文章部分。
   - 委派编辑不承担新增研究；事实或来源缺口按上述顺序交回研究端，不默认联网补齐。编辑者先完成双清单协调、全文双向语义与阅读验收、全部文件及审计更新，再按统一执行规范第2节最后写 `article.done`、交回写权并直接给出简短非空final；盲提取者在本职责自查完成后同样交回 `article-second-pass.done`。交回后不再追加复盘或重复全文读取；文件交回不证明原生运行或通知成功，异常按统一规范记录，不重复生产已有合格内容。
   - 编辑阶段的交接清单为当前运行目录中的 `article.md`、`article-baseline.md`、`article-second-pass.md`、`article-traceability.md`、`article.done`，登记实际路径及冻结母稿版本。连续阶段读取按Skill：同编辑、同输入/规则SHA、前次完整读取有证据且所需上下文仍在时，未变规范按需回查；新到的二次清单必须完整读取。换人、压缩后语义上下文缺失或版本变化则恢复必需完整读取，SHA相同本身不能证明仍掌握内容。完成标记、等待、接管及缺口恢复严格按统一执行规范第2—3节，不另设等待时限或自动重派分支。
   - `.done` 只是交接信号。协调前的Phase1由父级核验两原清单/母稿版本、完整性、唯一写权交回和明确阻断项；安全交接成立即由原编辑继续，不另派协调者或无条件再做一轮四文件全文终审。存在疑点即读取受影响内容，损坏或版本冲突先修复；确需换人按下述写权与恢复规则办理。协调完成后父级完整读取冻结母稿允许公开内容、两清单、映射及文章，核验实际 O/F/D/J/L、未销账项、正向覆盖与全文反向溯源；此最终验收不可缩成抽样或done检查。子任务状态或链接集合一致不能替代语义门控。
   - 写域必须分离：编辑线写 `article.md`、`article-baseline.md`、`article-traceability.md`，并在全部协调及全文验收完成后写最终 `article.done`；盲提取线写 `article-second-pass.md` 及其最后写入的 `article-second-pass.done` 冻结交接标记。双方原清单均冻结前，编辑者不得读取对方清单作协调；盲提取者始终不得读取编辑线材料。默认由同一编辑者在收到二次提取交接后继续协调，不为协调另派一位从头读入的编辑；两线不可互相等待对方的最终 `article.done`。协调前核验二次清单标记、版本及其写入者已交回不再修改；确需补漏时，确认原写入者已结束并转移对应文件的唯一写入权，只在原清单补漏区追加，保留原始内容和计数。若协调者换人，先按统一规范确认旧写入者终止再接管。
5. **叠加发布外壳**：使用启动合同中已核对站点规则的参数加入front matter、TOC和图片路径，按发布专项预检；这些外壳不得改变Skill已冻结的事实边界。头图准备遵守专项第5节，在选题稳定且具备依据和授权后独立进行，不阻塞已满足准入/资源条件的文章双线；它仍是发布前必须验证的产物，编号顺序不要求等待无内容依赖的图像完成才编辑。
6. **分别落盘**：
   - 资料库保存研究母稿，强调证据完整与可审计；Skill 不得覆盖或反向改写该文件；
   - 博客保存 report2article 编辑后的读者稿；周报 Prompt 指定的博客源文件路径覆盖 Skill 的默认输出文件名；
   - 两者不要求逐字或字数相同，但独立 O/F/D/J/L 信息必须全量对应，博客不得变成摘要版。
7. **发布验证**：严格按统一执行规范第6节完成源稿预检、Jekyll 构建及产物复检、双仓提交推送、真实远端 HEAD 与正文/头图 HTTP 及版本核验。文章和构建门控通过前，不提前提交或推送资料库。

交接按三个阶段顺序验收，禁止循环依赖：

1. **研究准入**：按共同标准冻结可公开母稿；局部缺口已限述/隔离并复验后可带局限进入编辑，只有共同标准列明的必要情形才整体阻断；
2. **文章保真**：检查经准入母稿的有效独立信息是否保留、是否出现新增失实或判断漂移；O/F/D/J/L 和反向溯源是复核工具，不以数量、行数或账本格式齐整替代语义判断；
3. **发布验证**：检查站点构建、Git 和 HTTP 的实际结果。机械失败必须如实记录，不得冒称成功，也不得否定已完成研究/文章，只修受影响步骤。

## 三、去重归 report2article，范围归周报 Prompt

- 周报 Prompt 只需告诉 Skill 哪些是必须覆盖的对象、模块、行业、专项和结论，不在 Prompt 中另写机械文章模板。
- 同一事件出现在多个研究组时，母稿可以保留来源差异供审计；读者稿由 Skill 判断哪些是重复表达、哪些是不同限定条件或证据，不得粗暴删除。
- TOP5、速查表、雷达、趋势、正文和建议之间的重复，由 Skill 通过原子信息基线和读者主线统一消解；不使用外部查重脚本。
- 如果周报要求某个固定栏目（例如模块状态矩阵、政策专项或云厂矩阵），将它作为“必须承载的信息形态”传给 Skill，而不是预先写死所有文章章节。

## 四、长报告强制处理

满足 Skill 定义的任一长文触发条件（对象不少于 8、约 6000 字/8000 token 以上、任一次读取截断）时，必须由 Skill 自己读取并执行其 `references/long-report-protocol.md`。

周报 Prompt 不再复制长文协议内容，只负责确保研究母稿和所有研究分块真实落盘、可完整读取。

长报告在当前运行目录内、与冻结母稿版本对应的位置保留三类纯Markdown产物：`article-baseline.md`、`article-second-pass.md`、`article-traceability.md`。清单内共同定义、直接可解析短引用、等义短记与真实差异详记，完整执行工作区Skill的 `references/info-checklist-template.md` 第1—2节；独立提取、真实补漏、原计数保留、全量映射及最终验收执行 `references/long-report-protocol.md` 第5—6节，不另维护重复细则。两原清单始终独立，不共享提取内容，不以同数/格式/引用可解析替代语义；三材料不是原句副本，也不另造第三/第四套完整清单。

父级按第二节区分中间安全交接与最终全文验收。最终确认经准入母稿的有效独立信息完整公开保留、无新增失实或判断漂移；纯行数、计数或格式缺项不作为事实不合格理由。真实遗漏只修受影响文章与映射，最终仍覆盖完整新版。

### 文章与账本落盘

> 研究组使用 `web_search` / `web_fetch` / `browser` 完成取证；本阶段使用文件工具完成读者稿和审计账本。

- 读者稿、首次信息清单、二次清单和映射账本，全部由模型使用 `read` 分段读取，再用 `write` / `edit` / `apply_patch` 分块落盘。
- 禁止为 report2article 新建或执行任何当期 Python、Shell、heredoc、内联代码或 CSV 生成脚本；不得用代码代替语义对读。
- `article-traceability.md` 使用 Markdown 勾选项记录：`编号｜母稿章节｜文章落点｜状态`。每完成一章就直接更新对应编号和累计进度，不等全文结束后一次性生成。
- `article-traceability.md` 的现有“当前进度”区按章节保存：已写章节、已核两侧编号/范围、未决差异和下一步。章节交接只证明该边界的进度，不得写成全刊 PASS。
- 每块落盘后立即用 `read` 检查文件尾部、章节完整性和账本勾选；发现漏项就在当前块用小补丁修正，禁止另写修复脚本。
- 中断接管前核对冻结母稿与规则文件 SHA、确认原写者已经结束，只续写“当前进度”中尚未完成的边界。已核且输入未变的证据可以复用，但接管者仍须读取完成续写所必需的输入；不得声称无需完整读取。输入变化时只重验受影响边界，同时保留最终全文双向核验。
- 可在同一工具轮次发出多个互不依赖且已获准的读取或检查；依赖结果的写入必须后置。正文仍只由模型使用文件工具编辑；固定 helper 仅承担机械检查，不生成或改写正文。不增加临时脚本、长 shell 链，也不写入运行时未白名单的工具名。等待期间只读简洁进度、文件尾部或变化，不按固定间隔反复全文读取。
- 最终仍须完整读取两份清单、映射和文章全文，按 Skill 协调两份独立原清单并反向溯源文章；逐项确认差异依据及语义对应、经准入母稿的有效独立信息无遗漏、无新增事实或判断漂移。映射用于定位真实内容问题；计数相同、勾选状态或格式完整度均不替代语义验收，也不因纯格式未齐自动阻断发布。

若“文章字数目标”和有效独立信息保真发生冲突，先合并重复表达、压缩非独立背景和改善信息形态；仍无法同时满足时，保留有效独立信息并如实超出字数目标，禁止为了卡字数静默删除内容。只有真实内容保真问题未解决时才阻断文章准出。

## 五、配图职责边界

- 每期必须生成的博客头图属于周报发布工程，由各周报 Prompt 规定文件名、风格轮换、生成优先级和 HTTP 验证；它不属于 Skill 默认的正文配图目录规则。
- `report2article` 只判断正文是否需要图表、流程图或示意图。当前周报默认只授权实际生成“本期头图”；除非周报 Prompt 另有明确要求，正文额外配图只给方案，不自动生成文件。
- 正文图表若实际生成，仍必须只使用母稿数据，并带标题、图注、来源和替代文本。

## 六、发布准出与真实终态

进入提交/推送前确认：研究母稿已按共同标准准入；文章保留经准入母稿的有效独立信息；无新增失实、关系或判断漂移；去重未删除不同限定条件、不同来源或独立结论。长报告二次派生和三份账本用于完成上述语义复核，不把纯计数、行数、表格或账本格式问题升级为事实硬闸。

源文件预检、站点构建及产物复检、双仓真实远端、线上正文与头图版本按统一执行规范第6节验证。任一发布机械步骤失败都不得宣称“博客已验证/已发布”；保留研究稿、文章和已完成发布证据，只修受影响步骤并记录恢复点，不新造恢复系统。

最终汇报按统一执行规范第7节给出真实阶段与终态，并报告可取得的实际 O/F/D/J/L、保留局限和发布证据。只有相应证据真实通过时才可使用：

`研究准入完成｜report2article 已执行｜有效独立信息已保真（O=<n> / F=<n> / D=<n> / J=<n> / L=<n>，可取得时）｜无新增失实/判断漂移｜博客已验证`
